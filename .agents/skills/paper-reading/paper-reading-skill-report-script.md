# paper-reading Skill 汇报讲稿

## 开场

大家好，今天我想介绍的是我做的一个 Codex skill：`paper-reading`。

我做它的出发点很简单：现在很多 AI 都能“总结论文”，但真正读论文时，我遇到的问题不是缺一段摘要，而是缺一个稳定的阅读工作流。尤其是机器人、VLA、模仿学习、后训练这些方向，论文里经常有复杂的系统图、训练流程、实验设置和工程假设。如果 AI 只是快速生成一段流畅总结，很容易看起来有道理，但实际没有帮我真正理解论文。

所以这个 skill 的目标，不是替代人读论文，而是把“找论文、读论文、记笔记”这三件事组织成一个更可靠的流程。

## 以前用普通 AI 读论文的痛点

以前我直接把 PDF 或论文链接丢给普通 AI，常见问题主要有三类。

第一类是搜论文不够可靠。  
如果只是泛泛地问“最近有什么论文”，模型往往会给一些看起来相关但不一定适合我当前研究方向的论文。它不一定理解我的长期阅读习惯，也不会稳定区分顶会论文、arXiv 初稿、低质量论文或相关性很弱的论文。最后我还要花很多时间手动筛。

第二类是读论文不够深入。  
很多 AI 会跳过阅读过程，直接给一个总结。问题是，它经常把论文明确写的内容、实验真正验证的内容、以及模型自己推测的内容混在一起。对于技术论文来说，这非常危险，因为我们真正关心的往往是输入输出是什么、训练监督从哪里来、实验设置是否成立、结论有没有被验证。

第三类是 PDF 和图表处理不稳定。  
很多双栏论文经过文本抽取后，章节顺序、图表标题和正文会混在一起。普通 AI 如果直接相信这些抽取文本，就可能按错误顺序解释论文。同时，它对图表的利用也不够，关键框架图、模型结构图、实验表格经常只被简单带过，甚至完全忽略。

最后还有一个长期问题：一次对话生成的总结很难沉淀。  
读完之后，metadata、PDF、图像资源、Markdown 笔记和索引往往是散的。过几周再回来看，很难快速知道这篇论文属于哪个方向、解决了什么问题、和我之前读过的论文有什么关系。

## 这个 Skill 的整体设计

`paper-reading` 的设计可以概括成三层能力：

1. 搜论文：帮我找到更值得读的论文；
2. 读论文：帮我按结构真正理解论文；
3. 记笔记：把阅读过程沉淀成可维护的知识资产。

这三层不是孤立的。搜论文解决“读什么”，读论文解决“怎么理解”，记笔记解决“怎么复用”。如果只做其中一层，效果都不完整。

## 第一部分：搜论文功能

搜论文功能的目标，是让 AI 不只是帮我“查几篇论文”，而是结合我的阅读习惯和研究方向，主动推荐更值得读的论文。

比如我近期关注 VLA、机器人操作、后训练和视觉提示相关方法，那么它在推荐论文时，就应该优先考虑这些方向，而不是给一堆泛泛的机器学习论文。它还应该能根据我的历史笔记、已有论文库和当前问题，判断哪些论文更可能对我有价值。

另外，检索论文时还需要质量筛选。不是所有看起来相关的论文都值得深入读。这个 skill 的设计目标是尽量过滤掉低质量、来源不清、会议或期刊不够权威、实验不充分、或者和主题只是表面相关的论文。最后给我的不应该是一长串链接，而应该是一个排序后的候选列表：每篇论文为什么推荐、属于什么方向、可能解决什么问题、是否值得精读。

这样做的价值是减少前期筛选成本。以前我需要自己在 arXiv、Google Scholar、会议列表里反复搜索；现在我希望 skill 能先帮我完成第一轮过滤，把注意力留给真正值得读的论文。

## 第二部分：读论文功能

读论文是这个 skill 的核心。

它不是一上来就总结，而是先建立阅读地图。阅读地图包括论文要解决的问题、章节结构、关键图表、方法主线、实验主线，以及阅读时需要重点确认的不确定点。这个步骤很重要，因为它相当于先搭出论文骨架，再往里面填细节。

接下来，它会要求事实边界更清楚。比如一篇论文里，有些内容是作者明确声称的，有些是实验真正验证的，有些只是可以从图表或公式推断出来的，还有些需要看源码或补充材料才能确认。普通 AI 很容易把这些混在一起，而这个 skill 会尽量把它们分开讲。

它还会做多源理解。PDF 是最核心的来源，但遇到双栏排版、公式抽取错误、图表错位时，只看 PDF 文本是不够的。这个 skill 会结合 PDF、渲染页面、arXiv source、图表 caption、原始图片资源等多种来源交叉理解，减少因为 PDF 结构混乱导致的误读。

在图表和公式上，它也会更主动。读论文过程中，如果某个框架图或实验图对理解很关键，它会尝试从 source 中找到原始图片并展示出来，而不是只用文字转述。对于公式，它不只是输出公式本身，还应该解释公式每一项代表什么、来自哪里、在方法里起什么作用。必要时可以用表格列出来，让公式从“看起来很复杂”变成“每一项都能追踪”。

另外，读论文不是单向输出。读到一半时，我可以随时问论文相关或领域相关的问题。比如“这个 loss 和之前那篇有什么区别”“这里的 action chunking 是什么意思”“这个方法迁移到我的项目会有什么问题”。skill 的作用是把回答限制在当前论文、相关领域背景和明确推断范围内，而不是随口扩展。

## 第二部分解决的具体问题

这个读论文流程主要解决三个问题。

第一，解决 PDF 结构敏感问题。  
很多双栏论文抽取出来的文本顺序是乱的，图注和正文也可能混在一起。如果 AI 直接基于这些文本总结，就会生成顺滑但错误的解释。通过多源交叉检查，可以降低这种风险。

第二，解决图表利用不足问题。  
很多论文真正重要的信息在图里，尤其是框架图、模型结构图、实验对比表和 ablation 表。普通 AI 往往只总结文字，导致对方法机制理解不完整。这个 skill 会把关键图表纳入阅读流程，而不是把图当装饰。

第三，解决过度自信问题。  
普通 AI 经常在论文没写清楚时自动补细节。这个 skill 更强调“不知道就说不知道”，把论文事实、实验验证和工程猜测分开。这对于后续复现、写相关工作、做方法迁移都更安全。

## 第三部分：记笔记功能

读完论文之后，下一步是沉淀。

`paper-reading` 会根据原始论文和阅读过程中的对话，生成 Markdown 笔记。这个笔记不是简单摘要，而是尽量保留论文的问题背景、方法结构、输入输出、训练监督、实验结论、关键图表、公式解释、适用边界和我的追问。

Markdown 是主格式，因为它可读、可维护、适合放进 Obsidian 或其他知识库。必要时，也可以用少量 HTML 增强可读性，比如做一个论文信息卡、关键结论块、图表说明块或对比 callout。但 HTML 只是增强层，不应该把笔记变成一个难维护的网页。

此外，这个 skill 还会分类建立和维护论文索引。比如按年份、方向、主题、方法类型、数据集或任务进行组织。这样以后我想找“VLA 后训练相关论文”或“使用视觉提示的机器人论文”时，不需要重新搜索对话记录，而是可以直接从论文库索引里找到。

更重要的是，它会维护 metadata、PDF、图片资源和导航文件。也就是说，一篇论文不是只留下一段文字，而是形成一个完整条目：论文信息、原文、关键图、阅读笔记和索引入口都在一起。

## 和普通 AI 的对比

| 维度 | 普通 AI 读论文 | paper-reading skill |
|---|---|---|
| 搜论文 | 泛泛推荐，相关性和质量不稳定 | 根据阅读习惯和研究方向推荐，并做质量筛选 |
| 阅读方式 | 直接总结，容易跳过理解过程 | 先建立阅读地图，再分层解释 |
| 事实边界 | 容易把论文事实和模型推测混在一起 | 区分明确声称、实验验证、合理推断和待确认内容 |
| PDF 处理 | 容易被双栏排版和抽取错误影响 | 结合 PDF、渲染页、source、caption 和图表交叉理解 |
| 图表使用 | 经常忽略关键图表 | 主动展示和解释框架图、结构图、实验图 |
| 公式解释 | 可能只贴公式或粗略解释 | 输出可读公式，并解释每一项的含义和来源 |
| 交互提问 | 容易脱离当前论文泛泛回答 | 围绕当前论文和领域背景回答追问 |
| 笔记沉淀 | 一次性聊天结果 | 生成 Markdown 笔记，并维护 metadata、assets 和索引 |

## 一个典型使用场景

比如我最近要调研 VLA 后训练方向。普通做法是我先自己找论文，筛选一批，再把 PDF 丢给 AI 总结，最后手动整理笔记。这个过程里，每一步都容易断掉：推荐不准、总结太浅、图表没看、公式没解释、笔记也不成体系。

使用 `paper-reading` 后，理想流程是：

1. 先根据我的研究方向推荐一批近期高质量论文；
2. 对候选论文做初筛，说明为什么值得读；
3. 对选中的论文建立阅读地图；
4. 结合 PDF、source、图表和公式进行分层解释；
5. 读的过程中随时回答我的追问；
6. 最后生成 Markdown 笔记，并放入论文库索引。

这样它不是只帮我“读一篇论文”，而是帮我维护一个持续增长的研究知识库。

## 边界和取舍

我也想强调一下边界。这个 skill 不是为了让 AI 完全代替人判断论文价值，也不是承诺所有图表和公式都能自动处理正确。它更像是一个受约束的研究助手：把重复、易错、需要结构化的部分交给 AI，同时保留事实边界和人工判断。

所以它的核心不是炫技，而是降低读论文过程中的摩擦：少花时间筛低质量论文，少被 PDF 抽取错误误导，少被流畅但不可靠的总结欺骗，多保留可以复用的笔记和证据。

## 总结

总结一下，`paper-reading` 想解决的是“AI 读论文不稳定、不可追踪、难沉淀”的问题。

它把论文阅读拆成三个阶段：搜论文、读论文、记笔记。搜论文阶段解决读什么；读论文阶段解决怎么理解；记笔记阶段解决怎么复用。

对我来说，它最大的价值是让 AI 从一个一次性问答工具，变成一个长期可用的研究工作流助手。最后得到的不只是一段摘要，而是一套可以继续追踪、复查和扩展的论文知识资产。
