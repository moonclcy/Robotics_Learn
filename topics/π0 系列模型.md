# π0 系列模型详解

> Physical Intelligence(PI)的机器人基础模型全家系,VLA 领域当前最系统化的产品线。

## 一、时间线

| 模型 | 发布时间 | 核心突破 | 一句话总结 |
|---|---|---|---|
| **π0** | 2024-10-31 | 首个 VLM + flow matching action expert 的通用策略 | 开山之作 |
| **π0-FAST** | 2025-02-04 | FAST 动作 tokenizer,纯自回归架构,训练快 5× | 开源版本 |
| **π0.5** | 2025-04-22 | 异构数据 co-training,开放世界泛化 | 能进没见过的家 |
| **π\*0.6** | 2025-11-17 | Recap RL(advantage-conditioned policy) | 从真实经验中强化学习 |
| **π0.7** | 2026-04-16 | 可操控性(steerability)+ 组合泛化 | 一个模型顶多个专家 |

**注意**:模型编号并非严格线性,`π*0.6` 是引入 RL 方法后的分支,`π0.7` 是主线继承者(整合了 π0.5 的数据策略和 π*0.6 的 RL 蒸馏数据)。

## 二、π0(2024-10)—— 奠基之作

**架构**:
```
[图像 + 语言 + proprio]
   ↓
PaliGemma 3B (VLM backbone)         ← 提取 KV cache
   ↓ cross-attention
Action Expert ~300M                 ← 独立的小 transformer
   ↓ flow matching
Action Chunk (50 步, 20Hz → 2.5 秒)
```

**关键设计**:
- **Backbone = PaliGemma 3B**:Google 开源 VLM,视觉 encoder 是 SigLIP
- **Action Expert 独立**:不共享 backbone 权重,是个 300M 的小 transformer,专门做 flow matching 去噪
- **50 步 action chunk**:50Hz 控制下 = 1 秒动作;20Hz 下 = 2.5 秒
- **Flow matching**:5~10 步推理,比 diffusion policy 快得多
- **跨本体训练**:混了 8 种以上机器人的数据(单臂、双臂、移动)

**评估环境**:与训练环境接近(不专门测泛化)

**参考**:[[VLA 训练与基础概念#4 Flow Matching(流匹配)]]

## 三、π0-FAST(2025-02)—— 开源 + 新 tokenizer

**核心贡献**:**FAST(Frequency-space Action Sequence Tokenization)**动作 tokenizer,让 VLA 可以纯自回归训练。

**FAST 的思路**:
```
动作 chunk (50 × 7) 
   ↓ 每维单独做 DCT (Discrete Cosine Transform,离散余弦变换)
   频域系数
   ↓ 保留低频、量化 + 熵编码(BPE 一样的字节对编码)
   ~30 个 token
```

**为什么这样做**:
- 原始 RT-2/OpenVLA 的离散 token 是**每维每步一个 token**,50 步 × 7 维 = 350 个 token,序列长得爆炸
- DCT 后能量集中在低频,少量系数就能重构完整轨迹
- 熵编码进一步压缩重复模式(如"保持不动")
- 最终一个 50 步 chunk 只需 ~30 个 token,和文字长度相当

**架构变化**:
```
[图像 + 语言 + proprio]
   ↓
PaliGemma (2.9B)                    ← 唯一的模型,没有 action expert
   ↓ next-token prediction
FAST action tokens (~30 个)
   ↓ FAST 解码
Action chunk (50 × 7)
```

**关键效果**:
- 训练收敛比 π0 flow matching **快 5 倍**
- 纯自回归,和 LLM 训练完全一样,基础设施好复用
- **权重开源**(π0 权重也一并开源),社区广泛使用

## 四、π0.5(2025-04)—— 开放世界泛化

**核心问题**:π0 只在训练环境里表现好,搬到新家庭就崩。π0.5 要解决"**能进从没见过的房子干活**"。

**架构**:**双通路解码**(高低层统一在一个模型里)
```
[图像 + 语言指令,如 "把厨房收拾一下"]
   ↓
PaliGemma (VLM backbone)
   ↓
分两路输出:
├── 离散自回归解码 → 高层子任务文本(如 "pick up the pillow")
└── Flow matching 解码 → 300M action expert → 50 步动作 chunk
```

这类似 **chain-of-thought**:模型先"想"下一步该干什么(语言子任务),再生成对应的动作。

**关键创新:异构数据 co-training**

| 数据类型 | 作用 |
|---|---|
| **Web 数据**(图文 caption、VQA、object detection) | 语义泛化,认识新物体 |
| **In-the-wild mobile robot**(100+ 家庭采集) | 目标本体的直接数据 |
| **In-the-wild static robot (ME)** | 多环境的静态机器人 |
| **In-office static robot** | 实验室高质量数据 |
| **Cross-embodiment (CE)**(π0 数据集) | 跨本体先验 |
| **Verbal instruction demos** | 语言指导数据 |
| **Subtask commands**(图像 + 该做什么) | 高层子任务对齐 |

**Ablation 揭示的关键**:

| 去掉什么 | OOD 成功率 |
|---|---|
| 完整 π0.5 | 94% |
| 去掉 web 数据 | 74% |
| 去掉跨本体 | 49% |
| 去掉多环境 | 31% |

**多环境数据是最关键的**(去掉掉 63 个点),web 数据主要帮认物体。

**Scaling 发现**:训练环境数超过 ~100 个后,泛化性能接近于"直接在测试环境训练"的 baseline —— 说明数据多样性比数据量更重要。

## 五、π*0.6(2025-11)—— 从经验中学习(Recap RL)

**核心问题**:π0.5 是纯模仿学习,遇到没见过的失败状态会崩(compounding error)。要让机器人**从真实执行经验里改进**。

**Backbone**:5B VLM(比 π0.5 略大),仍然是 VLM + action expert 结构

### Recap 方法(三阶段训练)

**阶段 1:Demonstrations(模仿学习)**
- 标准 BC,遥操作数据
- 问题:小错误会累积成大失败(compounding errors)

**阶段 2:Coaching with Corrections(专家纠错)**
- 遥操作专家**监视机器人跑当前策略**
- 出错时**接管**,提供正确动作
- 关键:这些纠错数据**针对模型实际会遇到的失败状态**,直接补上分布 gap

**阶段 3:RL from Autonomous Experience(自主经验强化学习)**

核心是 **advantage-conditioned policy**:

```
1. 训练一个 Value function V(s):预测某状态下最终成功的概率(像国际象棋预测胜率)
2. 计算 Advantage: A(s, a) = V(s') - V(s)   ← 这个动作让局面变好还是变坏
3. 训练策略时,在 prompt 里加上 advantage 值作为 conditioning
4. 推理时,提示模型"生成高 advantage 的动作" → 自动产生比训练数据更好的行为
```

**为什么不直接用 PG/PPO**:
- 传统 RL 需要丢弃坏数据、样本效率极低
- Advantage-conditioned 让**所有数据都能用**(好数据 + 差数据都有价值,靠 advantage 标签区分)
- 类似 Decision Transformer 的思路:把 RL 变成条件生成问题

### 实测任务

| 任务 | 挑战 | 结果 |
|---|---|---|
| **意式咖啡** | 长时序、倒液体、等待、擦拭 | 成功率翻倍,超 90% |
| **纸盒装配** | 折叠、卡纸恢复 | 工厂实测装了 59 个真箱 |
| **叠衣服** | 材质多变、新物品泛化 | 新家里连续叠 50 件新衣服不中断 |

失败率降低 2× 以上,越难的任务收益越大。

## 六、π0.7(2026-04)—— 可操控性 + 组合泛化

**核心问题**:π*0.6 的 RL 得针对每个任务专门做,能不能训**一个通才**,不用微调就到达专家水平?

### 可操控性(Steerability)

模型接受**多种条件信号**,不只是"做什么"还包括"怎么做":

| 条件信号 | 作用 |
|---|---|
| **语言指令** | 高层任务描述 + 细粒度"教练式"逐步指导 |
| **视觉子目标图像** | "做完这一步场景应该长这样"(可由轻量 world model 生成) |
| **Episode metadata** | 期望的质量、速度标签 |
| **控制模态标签** | 用关节控制还是末端控制 |

推理时的分层系统:
```
Task instruction
   ↓
[High-level policy] → 子任务指令
   ↓
[World model] → 视觉子目标图像
   ↓
[π0.7 action expert] ← 综合"子任务 + 子目标图 + metadata + 观测"
   ↓
动作
```

### 组合泛化(Emergent Compositional Generalization)

类比 LLM 的"能翻译 + 能输出 JSON = 能翻译成 JSON":

**具体例子**:
- **空气炸锅**:训练里只有 ~2 条"关空气炸锅"的数据(和实际任务差别很大),但结合网页预训练和其他机器人数据,能学会"操作空气炸锅"
- **跨本体迁移**:UR5e 双臂系统上**没有任何叠衣服的训练数据**,但直接就能叠,成功率 = 有 375 小时经验的遥操作专家首次尝试的水平
- **不用微调达到专家水平**:单个通才模型在叠衣服、做咖啡、装箱上的表现,匹配或超过用 Recap RL 专门训练的专家模型(π*0.6)

### 训练数据策略

关键洞察:**简单混合数据不 work**,必须给每条数据加"策略元数据"(strategy metadata):
- 遥操作演示 → 高质量标签
- 自主执行的成功轨迹 → 中等质量
- 各种质量的自主轨迹 → 用对应质量标签
- **π*0.6 RL 训练时收集的经验也蒸馏进来**,标上"高质量高效率"

推理时提示"高质量、快速执行",模型就从各种数据里提取相应的行为模式。

## 七、演化脉络总结

```
π0                  → 奠定 VLM + flow matching 架构
  ↓ 换 tokenizer
π0-FAST             → 纯自回归,训练快 5×,开源
  ↓ 加异构数据 co-training + 高低层双通路
π0.5                → 开放世界泛化,能进新家
  ↓ 加 Recap RL 三阶段
π*0.6               → 从真实经验强化,专家级性能
  ↓ 加 steerability + 蒸馏 π*0.6 经验
π0.7                → 通才 = 多个专家,组合泛化
```

**关键设计决策的演化**:

| 维度 | π0 | π0-FAST | π0.5 | π*0.6 | π0.7 |
|---|---|---|---|---|---|
| Action head | Flow matching | 自回归 tokens | Flow matching | Flow matching | Flow matching |
| VLM backbone | PaliGemma 3B | PaliGemma 2.9B | PaliGemma 3B | 5B VLM | 未公开 |
| 训练目标 | BC | BC | BC + 高层子任务 | BC + coaching + RL | BC + 蒸馏 + steer |
| 数据 | 跨本体机器人 | 同 π0 | +web/多环境/verbal | +自主经验+纠错 | +具质量元数据 |
| 主要能力 | 通用抓放 | 训练快 | 新环境泛化 | 长时序稳定 | 组合泛化 |

## 八、和力信息融合研究的关系

参见 [[力信息如何融入模型]]。π0 系列对力融合研究的意义:

1. **π0 / π0.5 是当前主流 base model**:FoAR、Force-VLA、FACTR 等力融合工作大多在 π0 上加东西
2. **Action expert 是天然的融合点**:力信息可以通过 cross-attention 进 action expert(不影响 VLM backbone)
3. **π0.7 的 steerability 框架**给了新可能:力信号可以作为一种"conditioning modality"接入,和视觉子目标、语言指令并列
4. **π*0.6 的 Recap RL** 特别适合力控任务:接触任务的成功/失败信号明确,advantage function 好学
